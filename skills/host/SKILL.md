# /mcp-use:host

Arguments: `$ARGUMENTS` = `<host> <mode>`. `host`: `chatgpt` or `archestra` (installed-server Route A; for a single HTML Owned App use `/mcp-use:archestra-app` instead). `mode`: `audit` (default; read-only), `add` (close the gaps for a host the project does not serve yet), `fix` (apply fixes to findings). One engine does all three: a gap analysis against `${CLAUDE_PLUGIN_ROOT}/data/hosts/<host>.checklist.json`. Read `references/gap-analysis.md` first.

1. **Scope.** Run `mcp-use-detect --json`. Continue only for a Node project with an mcp-use server (`M-USE-SRV`); otherwise print the scope notice from `/mcp-use:start` and stop. For `add`, record the host by writing `hosts: [...]` (every host already declared plus the new one) into `.mcp-use-plugin/settings.md`: create the file without asking, it is this plugin's own local state. Suggest adding `.mcp-use-plugin/` to the project's `.gitignore`, and edit `.gitignore` only if the user agrees.
2. **Evidence.** Run `mcp-use-scan --host <host> --json` (static). Start the dev server as in `${CLAUDE_PLUGIN_ROOT}/skills/verify/references/ladder.md` rung 2, then `mcp-use-probe --url http://localhost:<port>/mcp --host <host> --calls <file> --json`; add `--ua chatgpt` for `chatgpt` when any tool declares `securitySchemes` (it sends one unauthenticated, empty-argument call to **every** protected tool, independent of the calls file: use it only against a local dev server).  Put only **read-only** tools (`readOnlyHint: true`) with sample arguments from their `inputSchema` into the calls file; never call a tool that writes unless the user says so.
3. **Judgment (required, never skipped).** The scan and probe decide only the checklist's `static` and `probe` items; every item whose `methods` includes `manual` needs someone to read the code. Delegate to the `host-reviewer` agent (host, project root, dev URL). It runs the same engines read-only, reads flagged code, judges the checklist's `manual` items, and returns findings in `references/finding-schema.md`. If the agent is unavailable, do it yourself with the same files.
4. **Report first.** Merge the scan, probe and reviewer findings, group by severity (error, warning, advisory) with `fix_mode`, and write them to `.mcp-use-plugin/reports/<host>-<date>.json` before changing anything. Items marked `submission_only` are TODOs with an owner, not errors in development.
5. **`audit`:** stop here. Print counts, the findings, and the next command (`/mcp-use:host <host> fix`).
6. **`add` / `fix`:** follow `references/fix-safety.md`. Ask which findings to take on (AskUserQuestion, grouped by severity) unless the user said "all". Apply `auto` fixes with `mcp-use-scan --host <host> --fix` (it applies every `auto` finding in the files it scans and cannot pick individual findings: scope it with `--file <path>`, or apply only the chosen ones by hand); apply `suggest` and `manual` ones yourself, reading the cited reference first (`${CLAUDE_PLUGIN_ROOT}/skills/host-<host>/references/`). Owned-App HTML files the scan reports (host `archestra-owned`) are fixed with `archestra-app-lint --fix`, not `mcp-use-scan --fix`. One logical change per finding.
7. **Re-audit** (steps 2 to 3 again) and print before/after counts per severity. For `add`, also re-run every other host already declared in settings to prove nothing regressed. Remaining items must each have a reason (waived with a note, manual, or submission-only).
8. **Live check.** Tell the user how to try the app in the host (`${CLAUDE_PLUGIN_ROOT}/skills/verify/references/ladder.md` rung 5; for Archestra, ask for their Archestra URL and never install one). Without access, report it UNVERIFIED with the reason.

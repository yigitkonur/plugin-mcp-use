# Auth debugging (mcp-use 2.11.0)

Symptom to fix for OAuth servers, plus per-provider gotchas and what the auth endpoints really return. Setup and decisions are in `auth.md`; this file is for when it does not work.

Evidence codes. **T** = installed types (`dist/oauth/*.d.ts`, `dist/context.d.ts`, `dist/config.d.ts`). **J** = installed JS (`dist/oauth/*.js`, `dist/chunk-4ICJVJOI.js`, `dist/gate-5X3JUL36.js`, `dist/index-node.js`). **R** = observed run on 2026-10-20 (S23): `oauthCustomProvider` + `createJwtVerifier`, throwaway local ES256 issuer, `mcp-use dev --port 3731`, `requiredScopes: ["read"]`, tool `checkout` with `oauth2 scopes ["orders:write"]`. **D** = docs.mcp-use.com/v2/typescript/server/authentication/providers/<name>.md. Tokens below are throwaway, signed with a key generated for the run.

Shared request used in the checks (`$URL` = server origin):
`curl -si -H 'Content-Type: application/json' -H 'Accept: application/json, text/event-stream' [-H 'Authorization: Bearer <token>'] -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' $URL/mcp`

## Debugging checklist

| Symptom | Likely cause | Check | Fix | Evidence |
|---|---|---|---|---|
| 401, `error_description="Authentication is required for this request."` | No `Authorization` header. mcp-use says `error="invalid_token"` even for a missing token | Read the `www-authenticate` header; `resource_metadata=` is where the client must discover the IdP | Client must start OAuth from that URL, or send a bearer token | R |
| 401, `JWT verification failed` | Signature, `iss`, `exp`, algorithm or JWKS key failed. The response never says which | Restart the server with `MCP_USE_OAUTH_DEBUG=1`. Stderr prints `[oauth-debug] JWT verify failed: JWTExpired` / `JWTClaimValidationFailed: unexpected "iss" claim value` / `JWSInvalid: Invalid Compact JWS`, plus `header=` and `payload=` (iss, aud, azp, sub, exp, iat, nbf, client_id, scope, typ, jti, now) | Fix the named cause. The debug log prints claims, so use it in dev only | R, J |
| 401, `JWT verification failed` and the debug log says `unexpected "iss"` | Issuer string differs by even a trailing slash. `iss=http://localhost:3732/` failed against `http://localhost:3732`. `oauthAuth0Provider` builds its issuer WITH a trailing slash (`https://example.us.auth0.com/`) | Compare `payload.iss` in the debug log with `issuer` in `createJwtVerifier` or `curl $URL/.well-known/oauth-authorization-server` -> `.issuer` | Make the verifier `issuer` identical to the token `iss` | R |
| 401, `Token audience does not include the protected resource` | `aud` is not the resolved resource. Failing in R: another host, `.../mcp/` with trailing slash, origin only (`http://localhost:3731`) | `curl $URL/.well-known/oauth-protected-resource/mcp` -> `.resource`; decode the token `aud` (`cut -d. -f2 <<<"$T" \| base64 -d`) | Create the IdP API/resource with the identifier exactly equal to `.resource`. Fix `resource` or `MCP_URL` if `.resource` is wrong | R |
| 401, `Token audience claim must be a string or string array` | Token has no `aud` (IdP did not bind it to a resource) | Debug log `payload=` has no `aud` | Make the IdP issue resource-bound tokens (RFC 8707 `resource` parameter) | R |
| 403, `error="insufficient_scope"`, `Additional permissions are required: orders:write.` | Token lacks a scope. 403 not 401 | `www-authenticate` `scope=` is the full needed set (`read orders:write` = `requiredScopes` plus the tool's scopes); compare with the token `scope` claim | Request the full set at sign-in; list them in `scopesSupported` | R |
| 403 `Additional permissions are required: read.` for every call although the user signed in | Scopes are read only from the `scope` claim (string or array). A token with scopes under another claim (for example `scp`) has none. Observed with an empty `scope` | Debug log `payload=` shows `scope` | Map the claim in a custom verifier (`AuthInfo.scopes`), or drop `requiredScopes` | R, J |
| ChatGPT sees HTTP 200 + `isError: true` and no 401 | Expected. Only `tools/call` gets the in-band challenge: missing token, invalid token (`JWT verification failed`) and `insufficient_scope` all returned 200 with `_meta["mcp/www_authenticate"]`. `tools/list` with `User-Agent: ChatGPT/1.0` and no token is still 401 | Same `curl` with `-H 'User-Agent: ChatGPT/1.0'` and a `tools/call` body; `node bin/mcp-use-probe --url $URL/mcp --ua chatgpt --json` | None needed | R |
| Client reports "no protected resource metadata" or 404 on `/.well-known/oauth-protected-resource` | Only the path-suffixed document exists: `/.well-known/oauth-protected-resource/mcp` is 200, the bare path is 404. Authorization-server metadata is `/.well-known/oauth-authorization-server`; `.../oauth-authorization-server/mcp` is 404 | `curl -si $URL/.well-known/oauth-protected-resource/mcp` | Use the URL in `resource_metadata=` | R |
| Behind a tunnel or proxy the challenge and metadata name `http://localhost:3731/...` | No `resource`/`MCP_URL`, so the loopback fallback was used | `curl $URL/.well-known/oauth-protected-resource/mcp` -> `.resource`. With `MCP_URL=https://mcp.example.com`: `.resource` = `https://mcp.example.com/mcp` and `resource_metadata=` follows it | Set `MCP_URL` to the public ORIGIN. Tokens must then carry `aud=https://mcp.example.com/mcp` (a localhost-aud token gives the audience 401) | R |
| Startup error `MCP_URL must be an absolute origin without a path` | `MCP_URL=http://localhost:3731/mcp` (origin plus `/mcp`) | Look at the env | Origin only. `basePath` (`/mcp`) is appended | R, D (scalekit) |
| Startup error `OAuth requires an explicit resource or MCP_URL when using server.fetch or listening on a non-local host` | `--host 0.0.0.0` or `server.fetch` with no `resource` or `MCP_URL`. The `listen()` variant message: `OAuth listen() on a public or wildcard host requires an explicit provider resource or valid MCP_URL.` | `mcp-use dev --host 0.0.0.0` | Set `MCP_URL` or `resource` | R, J |
| Startup error `OAuth resource path must exactly match basePath (/mcp)` | `resource` (or `MCP_USE_OAUTH_AUTH0_AUDIENCE`, `MCP_USE_OAUTH_KEYCLOAK_AUDIENCE`, which become `resource` when you pass none) lacks the `basePath` path | `env \| grep MCP_USE_OAUTH` | Full endpoint URL with `/mcp`, or unset the variable | J, D (auth0, keycloak) |
| Startup `Tool "x": noauth requires mixedAuth: true on the server. Without it, every request needs a token, ...` | `securitySchemes: [{ type: "noauth" }]` without `mixedAuth: true` | Server start log | Add `mixedAuth: true` | R |
| `mixedAuth`: `noauth` tool returns 401 `JWT verification failed` | A token that is sent is always verified. A stale or garbage token fails even on `noauth` tools | Retry with no `Authorization` header: 200 | Client must refresh or drop the token | R |
| `mixedAuth`: anonymous call to a tool with no `securitySchemes` is 401 | Omitted `securitySchemes` means sign-in. `tools/list` is public. `checkout`'s advertised scopes were `["read","orders:write"]` (provider `requiredScopes` merged in) | `tools/list` -> `securitySchemes` per tool | Add `[{ type: "noauth" }]` if it is public | R |
| Browser GET of the MCP URL shows JSON 401 | With OAuth the landing page needs a bearer token (`Accept: text/html` GET got 401) unless `publicLandingPage: true` | `curl -si -H 'Accept: text/html' $URL/mcp` | `publicLandingPage: true` (config) | R, T |
| Browser client blocked by CORS (metadata fine, `/mcp` not) | Metadata answers `access-control-allow-origin: *`, OPTIONS 204 echoing `Access-Control-Request-Headers`. `/mcp` has no CORS unless `cors` is set: OPTIONS got 401 with no CORS headers | `curl -si -X OPTIONS -H 'Origin: https://app.example.com' -H 'Access-Control-Request-Method: POST' $URL/mcp` | `cors: { origin: "https://app.example.com" }` + `allowedOrigins: ["app.example.com"]` gave OPTIONS 204 with `access-control-allow-origin`. A different Origin got 403 `Invalid Origin: evil.example.com`. No `access-control-expose-headers` was sent on the 401, so page JS may not read `www-authenticate` | R, T |
| Custom route is reachable without a token | Only the `basePath` route has the bearer gate: `server.get("/health", ...)` returned 200 unauthenticated | `curl -si $URL/health` | Add your own middleware | R |
| `error_description` = `Token verifier returned invalid authentication information` / `Token verifier did not return a validated protected resource` / `Token identity mapping failed` / `...must return user, payload, and string permissions` | Custom verifier or `mapAuthInfo` returns a wrong shape: needs string `token`, string `clientId` (may be `""`), string[] `scopes`, future numeric `expiresAt`, `resource` equal to the server resource; mapper needs `user`, object `payload`, string[] `permissions` | Strings from `index-node.js` | Return the full `AuthInfo` | J |

## Provider gotchas

Every factory falls back to `MCP_USE_OAUTH_*` env vars when the option is omitted (T `@defaultValue`). Missing value throws `<Provider> ... is required.` (R).
- **Auth0**: option `domain`, env `MCP_USE_OAUTH_AUTH0_DOMAIN`. A bare host works (`example.us.auth0.com`). No `audience` option, but env `MCP_USE_OAUTH_AUTH0_AUDIENCE` becomes `resource` when you pass none (R). `permissions` from the `permissions` claim, `roles` from `roles` (J). Dashboard: Resource Parameter Compatibility Profile, domain-level connections, an API whose identifier is the MCP resource, `rfc9068_profile_authz` dialect for `permissions` (D).
- **Clerk**: `frontendApiUrl` (env `MCP_USE_OAUTH_CLERK_FRONTEND_API_URL`), optional `audience` (blank throws `Clerk audience must be non-empty`). With `audience` it checks `aud`; without it, tokens are accepted by issuer binding (J). `roles` is `[org_role]` or `[]`; `permissions` come from `org_permissions` (J). Dashboard: enable DCR, request `user:org:read` for organization context (D).
- **WorkOS**: `subdomain` (env `MCP_USE_OAUTH_WORKOS_SUBDOMAIN`); a path throws `WorkOS subdomain must be a hostname or HTTPS origin` (R). No `audience`. `ctx.auth.clientId` may be undefined (T, `context.d.ts`). Dashboard: DCR, Client ID Metadata Document, MCP endpoint as Resource Indicator (D).
- **Supabase**: `projectId` (`MCP_USE_OAUTH_SUPABASE_PROJECT_ID`) or `supabaseUrl` (`MCP_USE_OAUTH_SUPABASE_URL`, wins; `http://127.0.0.1:54321` accepted, non-local `http` throws), `jwtSecret` (`MCP_USE_OAUTH_SUPABASE_JWT_SECRET`, `< 32 bytes` throws `Supabase jwtSecret must be at least 32 bytes`) selects HS256, else ES256 via `<url>/auth/v1/.well-known/jwks.json`; default `audience` is `"authenticated"` (R, J). `permissions` is only `aal:<level>`. `ctx.auth.clientId` may be undefined (T). Dashboard: OAuth 2.1 server, Dynamic OAuth Apps, an app-implemented consent route (D).
- **Keycloak**: `serverUrl` + `realm` (`MCP_USE_OAUTH_KEYCLOAK_SERVER_URL`, `MCP_USE_OAUTH_KEYCLOAK_REALM`); a realm containing `/`, `?` or `#` throws `Keycloak realm is invalid`; issuer `<serverUrl>/realms/<realm>`, trailing slash on `serverUrl` accepted (R). `roles` = realm roles only; client roles are `permissions` as `resource:role` (J). Env `MCP_USE_OAUTH_KEYCLOAK_AUDIENCE` overrides `resource` (J, D).
- **Better Auth**: `authURL` (`MCP_USE_OAUTH_BETTER_AUTH_URL`) is the issuer verbatim, so it needs the base path (`.../api/auth`); endpoints derived: `oauth2/authorize`, `oauth2/token`, `oauth2/register`, `jwks` (R). Default `scopes_supported` `["openid","profile","email","offline_access"]`. Only `email, name, picture, email_verified, sid, is_anonymous/isAnonymous, roles, permissions` are mapped; add others with Better Auth `customAccessTokenClaims`. A separate Hono origin needs CORS + `trustedOrigins` and the `/.well-known/oauth-authorization-server/api/auth` route (D).
- **Scalekit**: `environmentUrl` + `resourceId` (`MCP_USE_OAUTH_SCALEKIT_ENVIRONMENT_URL`, `MCP_USE_OAUTH_SCALEKIT_RESOURCE_ID`). `resourceId` must start `res_` (`resourceId must start with "res_" (abc). A wrong value weakens audience binding.`). It is the required `aud`; `audience` is an extra `aud` value; both `environmentUrl` and `{environmentUrl}/resources/{resourceId}` issuers verify (R, J). `subjectType: "machine"` only when `sub` equals `client_id`/`azp`. `MCP_URL` is an origin with no trailing slash and no path (D).
- **Convex**: `authURL` (`MCP_USE_OAUTH_CONVEX_AUTH_URL`) = issuer including mount path (`https://x.convex.site/oauth`); non-local `http` throws. Also defaults `scopes_supported` to the Better Auth list (R). DCR is off by default in the Convex component (T). `permissions` is always `[]`; `user.clientId` from `cid` or `client_id` (J).

# Troubleshooting: server, runtime, protocol, tooling

Symptom to check to fix for mcp-use 2.11.0 and `@mcp-use/cli` 4.5.0. Every row was checked on 2026-10-20 against the installed package or a live run (S25). Evidence tags: `[live]` = run with `curl` or the CLI against `mcp-use dev` / `mcp-use start` from copies of the plugin's fixtures on Node 26.5.0; `[types]` / `[src]` = a file under `node_modules/mcp-use/dist/`; `[cli]` = `mcp-use <command> --help`.

Not repeated here because they live elsewhere: no server stdio, stateless requests, `export default server`, zod >= 4.2.0, no `ctx.elicit`/`ctx.sample`/`ctx.log` (`versions.md`, `config-and-lifecycle.md`, `tools-and-results.md`, `elicitation.md`), the ChatGPT HTTP 200 challenge and OAuth failures (`auth.md`, `auth-debugging.md`), view and CSP problems (`${CLAUDE_PLUGIN_ROOT}/skills/mcp-apps/references/troubleshooting-views.md`), and deployment (`deploy.md`).

Note on responses: a legacy POST (with `Accept: application/json, text/event-stream`) is answered as Server-Sent Events (`content-type: text/event-stream`, body `event: message` then `data: {...}`), not as plain JSON. Read the `data:` line when using `curl`.

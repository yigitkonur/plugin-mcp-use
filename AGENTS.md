# Maintainer rules

1. **Version bumps are automatic.** Installed copies update only when the plugin's `version` changes, so `.github/workflows/release.yml` bumps it (`scripts/bump-version.mjs`: patch by default, `#minor` or `#major` in a commit message of the push, or run the workflow by hand), tags `mcp-use--v<version>` and publishes a release on every merge to main that touches a shipped path. Do not bump by hand unless you want a specific number; a push that already changes the version is respected. `node scripts/validate.mjs` fails if `plugin.json` and `marketplace.json` disagree. Changes under `tests/`, `spikes/`, `evals/`, `.github/` and `AGENTS.md` do not release.
2. **Evidence over memory.** A rule, checklist item or reference states only what was read from the installed package types, a vendor doc, or an observed run, and cites a `data/sources.json` id on a `Sources:` line. No source, no claim.
3. **Every TS example compiles, or says why not.** The only unmarked blocks are two Next.js snippets (`advanced.md`) and one Vite config (`apps-sdk-ui.md`), each labelled as not compiled. Mark examples with `<!-- fixture: name -->` (must compile against mcp-use) or `<!-- fixture-bad: name -->` (must fail), then run `sh scripts/typecheck-fixtures.sh`. Official-SDK "before" code in the migration playbook uses `<!-- fixture-sdk1: name -->` / `<!-- fixture-sdk2: name -->` and is checked by `sh scripts/migration-workspace.sh --check`, which also compiles the migration fixtures F02, F03 and F11. Bumping `known_good` in `data/versions.json` re-runs both; a failing fixture blocks the bump until the reference is fixed.
4. **Quiet by default.** Hooks always exit 0, print nothing unless a signal is present, never block, make no network calls. Tests in `tests/` assert empty stdout for every control in `tests/controls/`.
5. **Size caps:** `SKILL.md` ≤ 150 lines, references ≤ 300 lines, knowledge skill descriptions ≤ 350 characters. One home per fact: link, do not restate.
6. **Knowledge skills are model-invoked, workflow skills are manual** (`disable-model-invocation: true`). Workflow skills cannot be started by the model; tell the user which command to type.
7. **No vendor text is copied** into this repository. No Archestra (AGPL) code or tests are vendored.
8. **Evals** (`evals/`, run with `claude plugin eval`) cost real model calls: run them only before a release, never in CI by default. `tests/evals.test.mjs` proves every regex grader passes a known-good output and fails a known-bad one (`tests/evals/<case>/{good,bad}/`); keep those samples in step with the graders.
9. **Parallel agent sessions** must stop servers by process id. Never `pkill -f` with a pattern broader than your own port: it kills other sessions' servers and `claude` processes on the same machine.
10. Run before every PR: `node scripts/validate.mjs`, `node --test tests/*.test.mjs`, `sh scripts/typecheck-fixtures.sh`, `sh scripts/migration-workspace.sh --check`, `claude plugin validate --strict .`.
11. **File references in the docs resolve.** A backticked path into another skill is written `${CLAUDE_PLUGIN_ROOT}/skills/<skill>/references/<file>.md`; inside a skill, `references/<file>.md` means that skill's own folder; README and AGENTS use paths from the repository root. `node scripts/validate.mjs` (lib/refs.mjs) fails on a missing file or a bare cross-skill path. A path that lives in the user's project goes in `ALLOW` in `lib/refs.mjs` with a reason.
12. **Test fixtures are tracked.** `.mcp-use-plugin/` is ignored except under `tests/fixtures/`; `tests/docs.test.mjs` fails if any other file under `tests/` is hidden by `.gitignore`, because a fresh clone would not have it.

# S7 — F14 rendered in ChatGPT through `mcp-use dev --tunnel`
Date 2026-10-20 · ChatGPT web (Pro account) driven with ego-browser · mcp-use 2.11.0 · F14 fixture (`tests/fixtures/f14`, with `vite.config.ts` from S19).

Steps and what was seen:
1. `npx mcp-use dev --tunnel --no-open --no-inspector --port 3711` printed `Tunnel: https://organisational-lime.tunnel.mcp-use.run/mcp`. `mcp-use-probe --url <tunnel>/mcp --host chatgpt --ua chatgpt` → 1 tool, 1 ui resource, 0 errors, 0 warnings, 1 advisory (CG-R03). `GET <tunnel>/mcp/inspector` → HTTP 404 (the Inspector is not reachable through the tunnel).
2. ChatGPT in this account has **no developer-mode toggle** in Settings; the flow is **Plugins → Add → "Add custom MCP server"** (mcp-use changelog 2.10.x says the same). Form fields: Name, Description, Connection (`Server URL` | `Tunnel`), Authentication (`OAuth` | `No authentication` | `OAuth or no authentication`; a native `<select>` with values `OAUTH`, `NONE`, `MIXED`), a risk acknowledgement checkbox ("I understand and want to continue"), **Create as a plugin**, then a **Connect** consent dialog ("ChatGPT may share relevant memories … and chats with this app"). The plugin then shows under Settings → Plugins with *Version: dev mode*, *Review status: DEVELOPMENT*, *Authorization supported/used: None*, and buttons Refresh tools, Edit, Uninstall, **Delete app**.
3. New chat, prompt "Use the mcp-use f14 test plugin to show product PROD-100 as a card." → "Worked for 20s", "Opened Show product", and a right-hand panel containing an iframe `https://mcp-app-<hash>.web-sandbox.oaiusercontent.com/?app=skybridge&locale=en-US&deviceType=desktop…` (885×674). The widget showed the card: "Precision screwdriver", "SKU: PROD-100", "$29.99", green "In stock" Badge from `@openai/apps-sdk-ui`, dark theme, transparent background. Screenshot: `spikes/evidence/S7-chatgpt-f14-render.jpg` (left navigation cropped out).
4. The server advertised only `_meta.ui.resourceUri` (no `openai/outputTemplate`, no `ui.domain`) and ChatGPT rendered it, using the default sandbox domain: `openai/outputTemplate` is not needed.
5. Cleanup: deleted the test chat, **Delete app** on the plugin, stopped the tunnel. The plugin list was back to its original entries. Developer mode was never needed or changed.

Not tested: picture-in-picture (mcp-use does not copy `pip` into `availableDisplayModes`, see S18), mobile, fullscreen via the expand control, entrypoints, settings, deep links. The panel placement (right-hand pane) is how this account's desktop web client opened an `inline`+`fullscreen` view; inline-in-thread placement was not observed.

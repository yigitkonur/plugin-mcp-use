# S16 — facts about `mcp-use client` / `screenshot` found while building fixtures
Date 2026-10-20 · mcp-use 2.11.0, `@mcp-use/cli` 4.5.0.
- `mcp-use screenshot … --json` on a fresh scaffold → `{"error":{"code":"client_install_required","message":"@mcp-use/client is required for this command.","details":{"nextSteps":[{"command":"npm install @mcp-use/client"}]}}}` (exit 1). `@mcp-use/client` is not in the template; `npm view @mcp-use/client version` → 2.4.5. **`verify` installs it as a devDependency after asking.**
- With the client installed, `--wait-for "[data-status='ready']"` and `--wait-for h2` → `browser_timeout: View did not become ready in time.` while `--wait-for body` and `--delay 2500` succeed. The selector is evaluated in the outer host page, not inside the view's iframe. **Use `--delay <ms>` (or `--wait-for body`), never an in-view selector.**
- Output: `{"path":…,"width":768,"height":119,"viewport":{…},"theme":"light"}` (PNG cropped to widget bounds, default width 768 = OpenAI inline card).
- Light theme capture of a view that paints no background shows the capture host's black backdrop with dark text (looks broken); the same unstyled view is also unreadable in dark theme (black on black, S22); it only looks right when the view paints its own colors for that theme. Judge contrast only for views that paint their own colors, and say so in the report.
- The official `mcp-server` template's tool sets only `readOnlyHint` and `openWorldHint` (no `destructiveHint`), so a fresh scaffold fails ChatGPT's explicit-annotations rule; the `mcp-apps` template sets all three.

# S27: what changed upstream between 2026-10-20 and 2026-10-25

Question: the weekly drift check reported 9 items. What actually changed, what breaks, what is new? Five read-only research lanes compared tarballs, `.d.ts` files, `--help` output and vendor pages. Everything below was observed on 2026-10-25 (macOS, Node 26.5.0). Method and where to look are in `AGENTS.md` ("Keeping up with upstream").

## mcp-use 2.11.0 → 2.11.2 (npm `latest`)
- `npm pack mcp-use@2.11.0` and `@2.11.2`, extract, compare: **all 120 `dist/**/*.d.ts` files are byte-identical**; `exports` (no `./server`), `engines` (node >=22.22.2), peer and other dependencies unchanged. The only `package.json` change: 2.11.1 pins `@mcp-use/cli` 4.5.1 and inspector 20.3.23, 2.11.2 pins cli 4.5.2 and inspector 20.3.24.
- GitHub release bodies for 2.11.1 and 2.11.2 are empty stubs ("Release 2.11.2 of mcp-use"); the docs changelog stops at v2.11.1. Tarball diffs are the evidence, not release notes.
- `node scripts/check-api-facts.mjs` passed against installs of 2.11.0, 2.11.2 and 2.12.0-canary.1.
- npm dist-tags: `latest` 2.11.2, `canary` 2.12.0-canary.1 (also `next`, `beta`, `dev`, `v1-legacy`: not releases of this line).
- Upcoming, **not released** (2.11.3-canary.0 and 2.12.0-canary.1, PRs #2910 and #2511), probed with a one-view server and Claude/ChatGPT user agents:

  | | 2.11.2 | 2.12.0-canary.1 |
  |---|---|---|
  | `view.domain = https://app.example.com/some/path`, ChatGPT read | `https://app.example.com/some/path` | `https://app.example.com` (normalized to the origin) |
  | Claude read, `ui.domain` | `<sha256 of the authored view.domain>.claudemcpcontent.com` | `<sha256 of the public MCP endpoint, e.g. https://wave.run.example.com/mcp>.claudemcpcontent.com` |
  | `MCP_URL` with a path | path dropped | path kept verbatim for the Claude hash (CSP and OAuth still use the origin) |

  2.11.3-canary.0 also sends a sampled `landing.viewed` telemetry event; opt out with `MCP_USE_ANONYMIZED_TELEMETRY=false`.

## @mcp-use/cli, inspector, client, create-mcp-use-app
- cli 4.5.0 → 4.5.2: top-level `--help` and all 13 subcommand helps identical; the tarballs differ only in a version string and the inspector peer range. Verify ladder re-run on a fresh scaffold (mcp-use 2.11.2, cli 4.5.2, inspector 20.3.24, client 2.4.5): `typecheck`, `build`, `dev`, `client connect/tools list/tools call/remove`, `screenshot --theme dark --delay 2500`, `start` all as documented.
- inspector 20.3.22 → 20.3.24: bug fixes (proxy strips `x-dev-*` headers, chat UI). `@mcp-use/client` 2.4.5 is still latest. `create-mcp-use-app` 2.1.0 unchanged.
- The scaffolder rewrites the template's `"mcp-use": "workspace:*"` from npm latest at run time, so a new scaffold pins `mcp-use` at whatever is latest then (2.11.2 today), not the scaffolder's own version. Templates pin `typescript ^7.0.2` and `@types/node ^22.20.0`; `blank`, `mcp-server` and `mcp-apps` all ship `landing.tsx`.
- `mcp-use --version` prints the resolved `mcp-use` package version, not the CLI version. There is no `generate-types` command (`typecheck` refreshes `mcp-env.d.ts`).
- Flags the CLI has that `cli.md` did not list: `build --path --entry --mcp-dir --views-dir`; `start --host --path --tunnel`; `typecheck --path --entry --mcp-dir`; `client connect -H/--header --no-oauth --auth-timeout --protocol auto|legacy|modern --no-open`; `client … tools call --timeout`; `screenshot -H/--header --inspector <url> --cdp-url <url>`.
- docs.mcp-use.com `llms.txt`: 259 pages, two lines differ (changelog moved to `v2/typescript/changelog.md`, a landing-page doc retitled). `v2/typescript/api-reference/cli-reference.md` matches the 4.5.2 help.

## Official MCP TypeScript SDK (sdk 1.32.1→1.32.2, server 2.3.1→2.4.0, node 2.1.1→2.1.2; ext-apps 2.0.3 unchanged)
- The three SDK "before" snippets and fixtures f02, f03, f11 compile on both pin sets; `mcp-use-probe --snapshot` then `--diff` on old vs new SDK prints `snapshots are equal` for all three.
- sdk 1.32.2 (PR #2958): `McpServer` installs handlers in the constructor when the capability is declared, so `registerTool` after `connect()` works (1.32.1 throws `Cannot register capabilities after connecting to transport`); a declared capability with nothing registered answers `tools/list`, `resources/list`, `prompts/list` with an empty list (was `-32601`) and advertises `listChanged: true`. A baseline taken on 1.32.1 can therefore show list "problem" rows that 1.32.2 does not.
- server 2.4.0: new Skills extension (SEP-2640) under `@modelcontextprotocol/server/ext/skills` (`SkillsExtension`, `SkillCatalog`, `loadSkills`, `nodeSkillFiles`; `attach()` is `@experimental`) and `SkillsClient`. The official `SkillSchema` requires `size` on resource entries and `ttlMs` + `cacheScope` on `skills/list` and `skills/get`; the recorded mcp-use 2.11.0 output (S17) has `digest` but none of those (inferred from the schema, not run against `SkillsClient`).
- server 2.4.0 (#3081): an `outputSchema` whose root is a `$ref` to its own `$defs` (zod `z.object().meta({ id })`) gets `type: "object"` and, on 2025-era connections, `structuredContent` is no longer wrapped in `{result}`. mcp-use 2.11.2 depends on server/core/client **exactly 2.3.1**, so it serves that schema without `type: "object"`: a ported schema can show a benign `CHANGED outputSchema` line.
- server 2.4.0 (#2762, #2960): `x-mcp-header` on a `number` parameter is rejected (tool not listed, `-32020` on call). Release note #3083 (not reproduced with zod): `$id`/`$ref` with an invalid scheme such as `my_tool:output` no longer compiles (fast-uri 3.1.8).
- node 2.1.2 widens `@hono/node-server` to `^1.19.9 || ^2.1.3` and needs server `^2.4.0`: bump node and server together. The API the playbook relies on is unchanged. No newer MCP specification revision than 2026-07-28.

## OpenAI / ChatGPT
- All five tracked developers.openai.com pages and `plugins/llms.txt` are byte-identical; `@openai/apps-sdk-ui` is still 0.2.2. The `mcp-extensions` spec changed (upstream commits #59, #61, #62 on 2026-10-21, spec/SDK 0.2.1): composer at-mentions are now supported on Web; a WebMCP section (Desktop only, tools via `document.modelContext`, "ChatGPT does not support the MCP Apps SDK's `App.registerTool()`"); `_meta["openai/group"]` `{ title }` on `ui/update-model-context` blocks; the display-mode default is stated as "if `_meta["openai/ui"]` is omitted entirely, legacy behavior, defaults to `inline`" (still no `pip`); deep-link schemes (`codex` on Desktop, `chatgpt` on iOS; `?path=` web link unchanged); numeric answers (`integer` and `number` form fields return JSON numbers; use a `string` field plus `pattern` for exact values); mobile `ui/message` supports `send: false` and `target: "new"`; `x-openai-input` `type: "file"` and `x-openai-preview` deprecated.
- Pages in `llms.txt` since before 2026-10-20 that the plugin had never read: `deploy/submission.md` (portal flow, domain verification at `/.well-known/openai-apps-challenge`), `deploy/app-review.md`, `deploy/submission-errors.md`, `guides/submit-claude-plugin.md`, `guides/security-privacy.md` (widgets cannot use `window.alert`, `prompt`, `confirm` or `navigator.clipboard`), `build/auth.md`, `build/mcp-events.md`, `build/monetization.md`, `deploy/desktop-only.md`.

Decisions: `known_good` moves to the versions above; fixtures compile at both the pins and npm latest; the facts above are written into the references, the checklist and one new static rule (CG-U20); the 2.12 canary behavior is documented as upcoming and version-gated.
